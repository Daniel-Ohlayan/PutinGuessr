# PitinGuessr

Угадайте место в России по Яндекс.Панорамам. Три режима:

- **Один город** — любой из 1070 городов России, панорамы строго внутри его границ;
- **Вся Россия** — случайные места по всей стране, как в GeoGuessr;
- **Дуэль** — асинхронная дуэль по ссылке: один и тот же сид, одни и те же 5 панорам
  у обоих игроков, сравнение счёта по раундам. Без сервера и регистрации.

5 раундов, до 5000 очков за раунд. Без регистрации и сервера — только браузер.

## Дуэли

1. На стартовом экране вкладка **«Дуэль»** → **«Создать дуэль»** — генерируется ссылка
   вида `…#duel/russia/<сид>` (она сразу копируется в буфер обмена). Отправьте её сопернику.
2. Соперник открывает ссылку или вставляет её на вкладке «Дуэль» → **«Присоединиться»**.
   Обе стороны играют **одни и те же 5 панорам**: сид детерминированно задаёт точки
   (из пула предзаготовленных позиций, см. ниже).
3. После игры каждый на экране результата нажимает **«Копировать»** у ссылки
   с результатом и отправляет её второму. По ссылке откроется сравнение счёта
   по раундам (ваш результат берётся из localStorage этого браузера).

## Пулы точек панорам

По умолчанию игра ищет панорамы живым поиском через `ymaps.panorama.locate` —
каждый вызов расходует суточный лимит бесплатного ключа (100 запросов на ключ,
общий для всех игроков сайта). Дуэли выбирают точки из **пула** —
предзаготовленного списка позиций панорам в `public/data/pools/russia.json`:
тогда на раунд уходит ровно один вызов `locate` по точной позиции, а точки
у обоих игроков гарантированно совпадают.

Пул собирает скрипт, который ходит в **публичный HTTP-эндпоинт Яндекс.Панорам**
(без API-ключа) и поэтому не тратит квоту JS API:

```bash
unzip -o data.zip   # один раз: данные городов и границы России
npm ci
node scripts/crawl-pool.mjs --pool russia --target 100
```

Запускайте несколько раз — скрипт дописывает новые точки и пропускает уже
собранные. Рекомендую набрать 500–1000 точек. Пока пул пуст, дуэль работает
через живой сидированный поиск (тратит квоту, но точки у игроков всё равно совпадают).

## Деплой

GitHub Pages: при пуше в `main` CI распаковывает `data.zip`, собирает проект
и выкладывает `dist`. Статика из `public/` (в том числе пул) попадает в сборку.
